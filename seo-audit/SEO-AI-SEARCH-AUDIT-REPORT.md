- `robots.txt` (generated by `web/app/robots.ts`): `Allow: /` for `*`, `Disallow: /admin`, `Disallow: /api/`, correct `Sitemap:` directive. HTTP 200, valid.
- **Issue C — /admin has no `noindex`:** it is a client-side login/dashboard page with no metadata export. `Disallow` in robots.txt does **not** equal `noindex` — Google may still show the URL (without content) in results. Recommend adding `noindex, nofollow`.
- Unknown tool slugs return a real HTTP 404 page (verified live) ✓
- **Known issue (Google-side):** Search Console reports "Sitemap could not be read" while the sitemap returns HTTP 200 with correct `text/xml`. Assessed as a Google fetch/cold-start issue; re-submission recommended after these changes.

Deprecated: `anthropic-ai`, `Claude-Web` (match nothing).

### 2.2 Current robots.txt (verified live)

```
User-agent: *
Allow: /
Disallow: /admin
Disallow: /api/
Sitemap: https://pdfedi.onrender.com/sitemap.xml
```

**Assessment:** all legitimate AI search and retrieval crawlers are currently **allowed** via the `*` rule. Nothing is blocked that shouldn't be. `/admin` and `/api/` are correctly disallowed.

### 2.3 Recommended robots.txt (requires approval — §7.6)

Keep the current rules and add **explicit, documented** AI crawler handling. Two options:

**Option 1 (recommended): allow everything legitimate (search + training).**
Rationale: PDFEDI is a free public tool; inclusion in training data helps AI assistants know about and recommend it. No sensitive content exists on public pages. Explicit `Allow` lines document intent and future-proof the policy.

**Option 2 (privacy-strict): allow search crawlers, block training crawlers.**
Adds `Disallow: /` for `GPTBot`, `CCBot`, `ClaudeBot`, `meta-externalagent`, `Google-Extended`, `Applebot-Extended`. Keeps ChatGPT/Claude/Perplexity/Bing/Google search visibility while opting out of model training.

Either way: keep `/admin` and `/api/` disallowed for all; never block `facebookexternalhit` (breaks link previews); never add unverified tokens.

## 5. Security & privacy risks

1. **/admin exposure:** admin login page is `Disallow`ed but not `noindex`ed — URL-only listing in Google is possible. No credentials or data leak (login requires token auth), but `noindex` closes the gap. No change to auth proposed.
2. **/api/ exposure:** correctly disallowed; no indexable content. No change proposed.
3. **User uploads:** processed server-side and auto-deleted; no user content is ever published to a crawlable URL — nothing for crawlers to leak. `llms.txt` will contain only public marketing/functional descriptions, no internal details.
4. **Training-crawler opt-out (optional):** if Option 2 (§2.3) is chosen, it only affects future training corpora; it does not expose or hide anything.
5. **No weakening of authentication/authorization** is proposed anywhere in this plan.
